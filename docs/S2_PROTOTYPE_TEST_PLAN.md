# S2 — خطة النموذج الأولي والاختبارات

## 1. الغرض

إثبات الحد الأدنى من صلاحية التوصية المقترحة دون إنشاء خدمة سحابية ودون بيانات حقيقية. النموذج لا يبني شاشات ولا ينفذ وظائف المراحل S3–S8.

## 2. مكونات النموذج

- `prototype/s2_local_architecture/core.py`: نموذج SQLite لعلاقات D1، قائمة المستخدمين، التزامن، التدقيق والتصدير.
- `prototype/s2_local_architecture/schema.sql`: نسخة SQL للمراجعة وخطة migrations المستقبلية.
- `prototype/worker_auth/auth.mjs`: تحقق JWT باستخدام Web Crypto فقط، متوافق مفاهيميًا مع Worker runtime.
- `tests/test_s2_architecture_prototype.py`: اختبارات البيانات والتفويض والتصدير.
- `tests/test_worker_auth.mjs`: اختبارات التوقيع والمطالبات وقائمة السماح.
- `scripts/validate_s2.py`: مدقق محلي حتمي بلا مكتبات خارجية.

## 3. البيانات الوهمية

يستخدم النموذج فقط:

- `uid-person-1` و`uid-person-2`.
- `client-001` باسم «عميل وهمي».
- `work-001` وعناوين وهمية.
- مفتاح RSA يولد داخل الاختبار ولا يحفظ.

## 4. حالات الاختبار

| ID | الحالة | المتوقع |
|---|---|---|
| S2-P01 | الشخص الأول ينشئ، والثاني يقرأ ويعدل لاحقًا | نجاح وتسجيل UID الثاني |
| S2-P02 | UID ثالث يحاول قراءة البيانات | رفض `AuthorizationError` |
| S2-P03 | تحديث بإصدار قديم | رفض `ConflictError` |
| S2-P04 | تعديل سجل التدقيق | رفض من قاعدة البيانات |
| S2-P05 | حذف سجل التدقيق | رفض من قاعدة البيانات |
| S2-P06 | تصدير JSON ثم استعادة | تطابق السجل والبيانات |
| S2-P07 | تصدير SQL | وجود schema والصفوف |
| S2-P08 | فحص schema لـ FR-027 | عدم وجود file/blob/attachment |
| S2-A01 | JWT صحيح وموقع وUID مجهز | قبول |
| S2-A02 | JWT صحيح لكن UID غير مجهز | رفض |
| S2-A03 | payload معدل دون إعادة توقيع | رفض التوقيع |
| S2-A04 | رمز منتهي أو audience خاطئ | رفض |

اختبار `S2-P04` و`S2-P05` ينفذان ضمن دالة اختبار واحدة، لذلك عدد اختبارات runner هو 11 مع تغطية 12 حالة موثقة.

## 5. أوامر التشغيل

```bash
python scripts/validate_s2.py
```

وفي CI:

```bash
python scripts/reconstruct_requirements.py
python scripts/validate_foundation.py
python scripts/validate_s2.py
```

## 6. معايير النجاح

- جميع اختبارات Python وNode ناجحة.
- `S2 LOCAL VALIDATION: PASS`.
- فحوص S1 ناجحة في نفس Pull Request.
- عدم وجود بيانات أو أسرار حقيقية.
- `docs/DECISION_LOG.md` غير معدل قبل اعتماد المستخدم.

## 7. ما لا يثبته النموذج

- الأداء الحقيقي ضمن 10ms CPU على Cloudflare Workers.
- اتصال Firebase أو D1 حقيقي.
- توافر الخدمات أو مناطقها أو latency.
- جلب مفاتيح Google العامة وتدويرها.
- استعادة D1 السحابية وTime Travel.
- واجهة المستخدم أو وظائف الأعمال الكاملة.

هذه البنود ليست ادعاءات نجاح في S2، بل مخاطر واختبارات لاحقة صريحة.
