# S5 PR-A Execution Contract

## Authority and scope

This contract implements the approved requirements, `docs/DECISION_LOG.md`,
`docs/TRACEABILITY_MATRIX.md`, and Issue #4. It covers only the S5 PR-A
domain/data/API foundation. It does not implement pricing, discounts,
payments, balances, settlements, reversal, or monthly closing.

## Data invariants

- Work events, title history, execution-status history, and archive history are
  append-only. Database triggers reject updates and deletes.
- A work title change is accepted only by `POST /api/works/:id/title` and
  requires a non-empty reason and the current work version. The generic work
  `PATCH` endpoint rejects title changes.
- Execution status changes are accepted only by
  `POST /api/works/:id/status` and require a non-empty reason and the current
  work version. The generic `PATCH` endpoint rejects status changes, including
  cancellation statuses.
- `CANCEL` and `ARCHIVE` requests are persisted as pending records. Approval
  requires the other allowlisted account, the request/work ownership match, and
  the request's captured work version. A request cannot approve itself or be
  finalized twice.
- Conditional mutations use the work/request version and ownership predicates
  inside the same D1 batch as their dependent history and audit writes. A stale
  or mismatched operation therefore produces no business side effects.
- All private endpoints require a valid Firebase ID token and an active,
  allowlisted D1 user. No endpoint performs financial mutations.

## Archive representation

The approved requirements describe archiving as closing a record while keeping
it searchable and analyzable, and separately require an execution status.
Therefore archive is represented by `works.archived_at`, `works.archived_by`,
and `works.archive_request_id`, with an append-only `work_archive_history`
record. Approval of an ARCHIVE request does not replace the current execution
status with `ARCHIVED`; this preserves the last execution state and avoids
losing execution history. `is_archived` is a derived read-model field.

## Upgrade contract

`tools/s3_cpu_gate/*/worker/migrations/0005_s5_domain_data_api.sql` is the
additive S4-to-S5 migration. It adds nullable archive metadata and the new
append-only/request tables, preserves existing rows, and installs the same
delete/update guards as the fresh schema. The migration is applied before the
Worker is switched to the S5 schema and is covered by the synthetic migration
test.

## API surface

Implemented private routes are:

- `POST/GET /api/works/:id/events`
- `POST /api/works/:id/title`, `GET /api/works/:id/title-history`
- `POST /api/works/:id/status`, `GET /api/works/:id/status-history`
- `GET /api/works/:id/archive-history`
- `POST/GET /api/works/:id/requests`
- `POST /api/works/:id/requests/:requestId/approve`

All responses carry the request correlation identifier generated by the Worker.
