# قاعدة القيم المالية الصحيحة

- الحالة: **معتمدة ضمن D-006**
- التاريخ: 2026-08-03
- النطاق: كل مخطط قاعدة بيانات، API، عملية حساب، سجل تدقيق، واستيراد أو تصدير مالي في المراحل اللاحقة.

## القاعدة

1. تخزن كل قيمة مالية بعدد صحيح من **الهللات** في عمود SQLite/D1 من نوع `INTEGER`، وتسمى الحقول بصيغة واضحة مثل `amount_halalas` أو `price_halalas`.
2. يمنع استخدام `REAL` أو `FLOAT` أو `DOUBLE` أو قيم JavaScript العشرية الثنائية لتخزين المال أو جمعه أو طرحه أو تقسيمه.
3. تقبل واجهات الإدخال مبالغ نصية مضبوطة بحد أقصى منزلتين عشريتين، وتحولها إلى هللات بتحليل نصي حتمي؛ لا يستخدم الضرب العشري العائم مثل `riyals * 100` بوصفه مصدرًا معتمدًا.
4. يجب أن تكون كل قيمة هللات `Number.isSafeInteger(value) === true`، وضمن المجال من `-9,007,199,254,740,991` إلى `9,007,199,254,740,991` هللة. يرفض النظام أي قيمة أو نتيجة وسيطة خارج المجال قبل الكتابة.
5. تطبق النسب باستخدام حساب صحيح وقاعدة تقريب موثقة تعتمد لاحقًا في مرحلة القواعد المالية؛ لا تفترض S2 قاعدة تقريب غير موجودة في المرجع.
6. تعرض الريالات وتنسقها عند حدود الواجهة والتصدير فقط، بينما تبقى القيمة الحاكمة داخل النظام بالهللات الصحيحة.
7. يجب أن تسجل سجلات التدقيق القيم المالية السابقة والجديدة بصيغة هللات صحيحة.

## السبب

الأعداد العشرية الثنائية لا تمثل كثيرًا من الكسور العشرية تمثيلًا دقيقًا. كما أن تطبيق Workers يستخدم JavaScript، ولذلك يلتزم المجال الآمن للأعداد الصحيحة حتى لا تفقد القيم دقتها عند الانتقال بين D1 والـWorker.

## التحقق المطلوب في المراحل اللاحقة

- تفشل migrations إذا أنشأت أعمدة مالية من نوع عائم.
- تفشل اختبارات API عند إدخال أكثر من منزلتين عشريتين أو قيمة خارج المجال الآمن.
- تختبر العمليات المالية عند الحدود، والقيم السالبة المسموح بها للحركات، والتراكم، والتقريب بعد اعتماد قاعدته.
